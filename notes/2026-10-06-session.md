## Root cause
The bar drew used categories with `█` and free/buffer space with the shade glyphs `░`/`▒`. In iTerm2 the shade glyphs are drawn a few pixels shorter than the full block (confirmed with a side-by-side window capture), so the runs had different heights.

- Every cell is `█`; kinds are told apart by colour. Free space uses the `subtle` theme colour (the engine's own colour for it is `inactive`, the same as System tools). The buffer keeps the engine's colour.
- `dimColor` together with a theme `color` had no visible effect in iTerm2, so it is not used.
- Also cleared two `claude plugin validate` warnings: added `author`, added `.catch` on the `session.compact` hook.
- Test updated: asserts one glyph across bar and legend, no shade glyphs anywhere, free run coloured `subtle`.

# Fourth task (same day): compaction animation, refresh after compaction, README (v0.4.0)

## Asked for
- On compact, the messages turn a darker colour (between the messages and free colours); when it is done the bar animates down to its new level.
- Compaction should refresh the bar (it did not); test for it specifically.
- README: the GIF is the main image, with no note about how it was made or its frame rate.

## Why the bar did not refresh after a compaction (measured with a probe mod, Claude Code 2.1.292)
- When `next(e)` of `session.compact` resolves, `$.session.usage({ breakdown: 'summary' })` still returns the old count. About 100 ms later it returns the new one.
- No `session.measure` is raised for the compaction (`context.tokens` is absent until the next response), and no `session.start` either. So the old refresh read a stale count and nothing asked again.

## What was built
- `Frame.dim` (0 to 1) eases with the rest of the frame; the messages are drawn `blend(messages, free, dim * 0.5)` in the bar and the legend (`blend` is in `hooks/cells.ts`).
- `session.compact` hook: dims before `next(e)`; afterwards `settle()` asks for the count every 100 ms (20 tries at most) and, when it moves, un-dims and slides. A skipped compaction un-dims at once. `precompute` and subagent compactions are passed through.
- `isCompacting` is a module variable, not `$.state`, so a reload during a compaction cannot leave the bar dimmed.
